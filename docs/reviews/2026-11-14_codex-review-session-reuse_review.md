### [P1] 源码哈希一致不足以定义同一修订 — 清单覆盖范围和审查语义未冻结 — 建议替换 §3 的判定依据，并扩充 §1、brief 模板

当前规则只比较被列出的源码。以下情况均可能误判为同一修订。

- 漏掉头文件、生成物、依赖锁文件、构建配置或影响行为的数据。
- 原文件未变，但新增文件被 glob、自动发现机制或配置加载。
- 路径、文件类型、符号链接目标、可执行位或文件缺失状态发生变化。
- 同一批文件用于不同 WP、审查范围或验收标准。
- 非 git 工作区只有零散哈希，没有完整的范围与基线记录。

**§3 建议替换为**

> - 会话复用同时要求项目身份、工作包/修订标识、审查对象定义、范围与验收标准、基线清单完全一致。`WP-xx/Rn` 用于标识，基线清单用于核验，两者同时满足才允许续跑。
> - 项目身份记录规范化绝对路径。基线清单记录相对路径、文件类型、存在或缺失状态、内容 SHA-256，以及影响本次审查的权限和符号链接信息。
> - 清单覆盖本次判断依赖的源码、生成物、依赖版本、配置与数据。对会自动发现文件的范围，同时记录文件集合及包含/排除规则，以识别新增和删除。
> - 发现相关输入漏记、变化或无法核验时，原结果标为 INCOMPLETE 或 STALE，重新冻结基线并新开会话。
> - `source-sha256` 清单完全一致是复用的必要条件。项目身份、审查对象、范围、验收标准及相关输入也必须一致。

**brief 模板“对象”节建议增加**

```text
- 项目身份与绝对路径 <...>
- 工作包及修订 <WP-xx/Rn>
- 审查对象定义 <工作树 / commit / 分支差异及固定对象 ID>
- 范围与验收标准 <...>
- 基线清单路径及清单 SHA-256 <...>
- 相关配置、依赖、生成物与数据 <清单或已知缺口>
```

“修订号 + 哈希”更便于管理，但修订号本身无法弥补清单遗漏。

### [P1] 前后哈希无法排除审查期间的瞬时变化 — 文件改动后恢复仍可能通过检查 — 建议补充 §1“基线冻结”

§1 已要求发送前、完成后核对，能发现持续存在的变化。仍有如下反例。

1. 开始时文件为 A。
2. 审查过程中其他会话改成 B，审查者读取 B。
3. 完成前恢复 A。
4. 前后哈希一致，报告实际混用了 A、B。

**建议追加**

> - 优先审查固定对象或独立的冻结快照。必须审查活动工作树时，编排者应协调相关写入在审查期间暂停，并在每次启动或续跑前、结束后核对完整基线。
> - 前后哈希一致只能证明两个检查时点一致。若已知审查期间发生过写入，或读取结果与基线不符，本次结果标为 STALE，即使结束时文件恢复原样。
> - 恢复原样后需要重新审查时，新开会话。原会话已接触中间版本，不能继续作为该冻结基线的审查会话。

这也覆盖了“resume 后上下文仍保存旧文件内容”的情况。检测到版本混入后，仅重新读取文件不足以恢复会话基线。

### [P1] commit 和分支差异缺少固定身份 — 相同目标源码可能对应不同 diff — 建议补充 §1，并由 §3 引用

例如，HEAD 文件完全相同，但比较基线不同，新增与删除的含义就会改变。分支名还可能在配额等待期间移动。

**建议追加**

> - 审查 commit 时，记录完整 commit 对象 ID，并明确审查整个提交状态，还是相对哪个父提交的改动。合并提交必须明确比较父提交或其他比较方式。
> - 审查分支差异时，记录解析后的完整 base、head、merge-base 对象 ID，以及比较方式，例如三点比较。续跑使用这些固定对象，分支名仅作为说明。
> - 审查工作树时，记录固定 HEAD、审查所用 diff、范围内 staged/unstaged 状态、未跟踪文件及相关输入清单。
> - 非 git 工作区使用工作包/修订标识与冻结文件清单建立基线，记录清单覆盖范围。
> - 审查者读取的文件内容必须对应记录的对象。使用工作树路径读取 commit 内容时，编排者须核验二者一致。
> - 对象、比较基线或比较方式变化时，新开会话。

### [P1] resume 的模型与推理档位未经核验 — §3 内部要求冲突 — 建议统一角色边界、§3 和 §4

角色边界要求“每次显式传 `-m`”，§3 却要求“续跑不要传 `-m`”。当前文本也没有证据证明 resume 必然继承 `gpt-6.1-sol` 与 `high`。§4 再次重复这一假设。

**建议用以下条目替换相关要求**

> - 每次调用均须核验实际模型、推理档位、工作目录和只读沙箱，包括 resume。默认期望值为 `gpt-6.1-sol`、`high`、本次项目目录和 `read-only`。调整档位时记录本次明确选定的期望值。
> - 编排者先依据本机 CLI 的帮助或已验证接口确定 resume 支持的参数。支持显式指定的参数应显式指定，随后核验本次调用的实际运行信息。
> - 上一轮启动头、原会话设置和命令行参数只作为配置记录。实际值以本次调用的有效运行信息为准。
> - 实际模型或推理档位不符时停止该次调用，并按期望配置重新运行。无法确认时标为 INCOMPLETE，保留未核验项。
> - 报告同时记录期望值、实际值及核验依据。

**NOT_RUN** — 本次未检查 CLI 帮助、resume 参数支持情况或实际继承行为，因此不提供未经核验的替换命令。

### [P2] session id 缺少唯一映射与调用级落档 — 并行工作包和同名输出容易串用 — 建议补充 §3，集中到 §5 维护

当前只要求“记下来”和“换新文件名”。同仓库多个 WP/Rn 并行时，依靠 topic 名或“最近一次会话”容易选错。§4 示例还遗漏了输出与日志文件。

**§5 建议追加**

> - 每条审查会话链建立一条映射，至少记录项目身份、WP/Rn、审查对象、基线清单摘要、会话链编号、实际 session id、期望及实际模型/档位、状态和报告路径。
> - session id 按 CLI 返回值原样保存。报告头和映射表均记录该值，通过完整映射选择会话，禁止使用 `--last` 选择正式审查会话。
> - 每次 CLI 调用分配独立调用编号，包括追问、配额续跑和失败重试。建议目录为 `WP-xx/Rn/codex-review/<baseline-id>/<会话链编号>/<调用编号>/`，分别保存 brief、原始日志、最终消息和运行元数据。
> - 创建调用目录时检查编号冲突。`-o` 指向本次调用的独立文件，禁止覆盖已有报告。日志和 brief 也使用本次调用的独立路径。
> - 同一 session 的调用串行执行。不同工作包或修订分别维护映射。
> - 单个调用状态和会话链汇总状态分别记录。后续补查发现缺陷时，更新会话链的当前结论，并保留此前报告。

**§3 建议增加失败回退规则**

> - resume 明确失败后，先确认原调用已终止并保存日志。session 不存在、不可恢复或上下文不可用时，新开会话，并记录替代关系及失败原因。
> - 新会话接收自包含的最小 brief，包含身份与边界、固定基线、范围、验收标准、未决问题、必要证据及上一轮报告位置。重新核对支持当前结论的关键证据。
> - 调用状态未知时先确认终态，避免与仍在执行的原调用重复运行。

### [P2] 复用例外已有原则但缺少可观察条件 — 固定窗口数字无法直接指导决策 — 建议替换 §3 的复用与例外条目

现有规则已经包含换角度调查、盲审和压缩例外。需要补齐范围边界、识别依据和信息传递方式。

**建议替换为**

> - 基线、范围和验收标准一致时，追问、换角度调查及补查优先续跑。同一修订内补充证据时，在增量 brief 中列出新增证据的路径、哈希、来源基线和待核问题。
> - 补充证据出现冲突时，重新核查受影响的结论。新增源码范围、相关输入或验收标准导致基线定义变化时，重新冻结基线并新开会话。
> - 用户要求盲审时，新开会话，并按盲审范围省略上一轮结论、缺陷提示及定向分析，同时保留必要的对象、边界和验收标准。
> - 从 CLI 公开日志或运行元数据确认是否发生上下文压缩，并记录可获取的当前上下文用量、窗口上限和压缩事件。累计 input tokens 与 cached tokens 不作为当前上下文占用。
> - 不将约 475k 窗口和约 150k 终态上下文写成通用阈值。以当前实际限制及下一步预计所需空间作判断。
> - 已确认压缩，或剩余空间不足以完成下一步补查时，新开会话，并提交自包含的最小 brief。无法观察上下文状态时记录 UNKNOWN。出现关键约束或证据遗漏时，按上下文不可用处理。

新会话沿用上一轮结论会影响盲审独立性，因此盲审需要独立的 brief 规则。

### [P2] 配额续跑存在无条件恢复表述 — 等待期间基线可能变化 — 建议让 §4 统一引用 §3，并收敛重复文字

§4 虽然写了“与 §3 同一规则”，随后的无条件续跑命令及“沿用模型”说明仍容易被单独执行。

**§4 配额条目建议整体替换为**

> - 出现配额耗尽提示时，将本次调用标为 INCOMPLETE，保存 session id、原始日志、已完成内容和提示的重置时间。重置前不立即重试，不自动更换模型或供应商。
> - 配额恢复后，先按 §3 核对审查对象、基线、范围、会话状态及实际运行配置。满足复用条件时续跑，基线变化时新开会话，原会话不可恢复时执行 §3 的失败回退流程。
> - 续跑使用独立调用编号及输出路径，增量 brief 重申只读边界、未决问题和相关证据。
> - 缩减本次读取清单时，保留完成原验收范围所需的内容。验收项目仍有缺口时保持 INCOMPLETE。
> - 跨天本身不改变修订身份，也不强制新开会话。缓存是否命中不作为复用资格条件，复用不保证节省 token 或费用。

给定数据支持“多数缓存命中来自轮内前缀复用”。单次 `cached=0` 无法确定固定的缓存失效时长。
