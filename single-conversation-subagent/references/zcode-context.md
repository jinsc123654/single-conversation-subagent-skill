# ZCode 子 Agent 上下文判断

**判定对象始终是 `--agent` 指定的子 Agent。** 占比 =（该子 Agent 最近一次已完成请求的输入 + 输出 + 下一轮余量）÷ 该子 Agent 实际模型窗口。`--parent` 只校验父子关系；`--catalog-session` 只定位近期模型目录，不读取那一主对话的用量，也不采用主对话模型窗口。

1. 不只在准备 `SendMessage` 时才查：所有角色在新开同一工作线的后续实例前，先判断是否有已完成、角色/目标/基线/授权相容的旧实例。工具相似不是充分条件，跨包也不自动排除。取得实际派发回执中的目标 `agent_...` ID 和宿主父会话 `sess_...` ID；不要用 SCS 会话 ID、角色名或主对话模型代替。续跑前等候真实完成回执，不向运行中的 Agent 发送消息来测容量。
2. 在当前主对话调用 `ListModels`，然后运行 Skill 随附的 Node.js 24.2+ 只读探针。工具文本可能不显示窗口字段，探针读取 5 分钟内同一调用的结构化宿主记录，并按精确 `provider/model` 匹配。

```bash
node "$HOME/.zcode/skills/single-conversation-subagent/scripts/zcode-context.mjs" \
  --parent 'sess_实际父会话' --agent 'agent_实际派发ID'
```

如果在当前对话核查别的父会话，额外传 `--catalog-session 'sess_当前对话'`，让探针用当前对话刚查的模型目录；`--parent` 仍是目标子 Agent 的真实父会话。历史查询得到的是最后一次已完成请求的用量，以及按当前宿主窗口换算的比例；不要把当前窗口冒充未经验证的历史配置。

- `used_percent` 按最近一次已完成模型请求的 `input_tokens + output_tokens` 计算。缓存输入已经包含在输入 token 中，不重复相加；不用累计账单或主会话用量。
- `projected_percent` 另加下一轮余量（默认 4096 token；预计更多时用 `--reserve N` 提高）。预计占用 **达到或超过 70%** 或宿主明确记录上下文超限时是 `ROTATE`；只有低于 70% 才是 `REUSE`。比较用未舍入的 token 数。
- `UNKNOWN`（如窗口未持久化、模型不匹配、记录不可核验或脚本不可用）不代表 0%。它必须来自实际查询或可核验的工具/脚本不可用证据；尚未调用 `ListModels`/探针不能记成 `UNKNOWN`。报告真实的 `reason` 或命令失败及缺项；如需继续，保守新开同角色，不伪造百分比、不循环重试。`REUSE` 只表示容量允许，不代替权限、基线、工作包和正式审查的独立性检查。

- 候选相容且 `REUSE` 时优先 `SendMessage`；有相容候选却新开时，记录容量以外的具体原因。长任务先 prepare 新 attempt，给出本轮范围、授权和证据目录；新 attempt 不等于新 Agent。旧执行未确认停止或资源未静止，不能凭探针决定续跑或重派。
- 派发前在现有协调记录或工具简报首部写一行 `dispatch_decision`（角色、实际候选 ID、相容性、探针 `decision/reason/projected_percent` 或具体不可用证据、选用工具及原因）。不要只在内部推理里提“考虑过复用”。首次/无相容候选/不同工作线/明确盲审时写明具体原因，无须运行无候选探针。
- 跨父会话核查只用于分析容量，不证明当前宿主可以 `SendMessage` 到旧实例；当前对话接手另一父会话的工作时，新开并带必要交接，不因探针 `REUSE` 改变寻址或授权边界。

例：同一设备的静置基线与下一轮对照可能属于同一工作线，即使分在两个工作包，也可核对目标与授权后判断续跑。最后一次请求 354,516 / 1,000,000 为 35.45%；加 4,096 余量后预计 35.86%，容量允许续跑。同线包级复核、收尾或操作预审也按此判断；只有相容且仍独立于被审实现的审阅员才可续跑，必须审查本轮对象并出具新回执。明确要求全新盲审时另开实例。
